# Create Skills — план работ

**Версия:** 0.1 · 2026-11-05
**Статус:** P0 и P1 закрыты: бандл `create-skills` установлен в профиль `desktop`, страница Skills показывает реальный каталог (12 скиллов, включая проектные и preset-слои).

## 1. Цель

Сделать скиллы в DSH управляемым активом проекта: страница **Skills** в боковой панели (как Plugins, Schedules, Context), установка из каталога по категориям с выбором «один / несколько / все», создание и правка скиллов, контроль бюджета системного промпта и A/B-сравнение двух версий скилла на одной задаче.

## 2. Что есть сейчас и чего не хватает

Есть:

- формат `<имя>/SKILL.md` с YAML-шапкой: `name` (kebab-case), `description`; опционально `whenToUse`, `metadata`, `disable-model-invocation`, `user-invocable`;
- корни: `<проект>/.dsh/skills` (приоритет 100), `<проект>/.agents/skills` (200), `~/.dsh/skills` (400), `~/.agents/skills` (500), встроенные (600); проектный слой перекрывает пользовательский;
- живой watcher: новый `SKILL.md` появляется в каталоге без перезапуска (проверено);
- у модели — каталог «имя + описание» и инструмент `skill`; у пользователя — `/имя` в композере.

Нет:

- страницы Skills и вообще UI управления скиллами;
- каталога доступных, но не установленных скиллов и категорий;
- операции «установить» (сейчас это ручное копирование папки);
- редактирования имени/описания;
- учёта того, сколько токенов каталог занимает в каждом запросе;
- сравнения версий.

## 3. Сценарии

1. **Установка по имени.** «Добавь скилл docx» → карточка с описанием, источником и весом → «Установить» → файлы в `<проект>/.dsh/skills/docx/` → скилл сразу виден.
2. **Установка по категории.** «Добавь категорию Документы» → 4 карточки с описаниями и чекбоксами → «Установить выбранные (2)».
3. **Установить всё.** Кнопка «Все» доступна, но показывает прогноз: «+4 скилла, +120 токенов в каждом запросе» и требует подтверждения.
4. **Создание с нуля.** Форма: имя, описание, когда применять, категория, слой (проект/пользователь), тело. Валидация kebab-case, уникальности, длины описания.
5. **Правка.** Изменение описания/тела; переименование с проверкой ссылок из других скиллов.
6. **Бюджет.** В шапке: «Каталог: 12 скиллов · ~430 токенов/запрос». Превышение порога (по умолчанию 1200) → баннер с предложением выключить лишние.
7. **Оптимизация.** «Выключить» ставит `disable-model-invocation: true`: скилл остаётся доступен по `/имя`, но исчезает из промпта модели. Удаление — отдельное действие.
8. **A/B.** Слева версия A и её чат, справа версия B и её чат; одна и та же задача уходит в оба; снизу — два ответа и оценка (ручная или авто-судья).

## 4. Этапы

Оценка — мои токены (вход + выход) и время работы без учёта вашего ревью. В оценку входит чтение API, код, установка, проверка.

### P0. Репозиторий и проектные документы — сделано

- Структура, README, PLAN, docs, каталог из 10 скиллов, `.gitignore`, лицензия, git-репозиторий.
- **DoD:** документы читаются, каталог валиден по схеме, решение по каждому спорному пункту записано в ADR.
- **Оценка:** 15–25k токенов, 1–1,5 ч.

### P1. Каркас плагина и страница Skills (read-only)

- Пакет `create-skills` с `dsh.bundle.patch` и `dsh.client`; иконка, локали en/ru, `meta.title`/`meta.description`.
- Host: сервис `skillStudio` — `list(projectRoot)`, `budget(projectRoot)`; чтение через `ctx.skills.list({ cwd })`.
- Client: запись в `sidebar.panellist` (id `create-skills`) и `main` (key `create-skills`); шапка, список скиллов, бейджи источника и веса, пустое состояние.
- Транспорт host↔client: спайк — `ctx.remote` (typert) против same-origin HTTP-маршрута `webServer.register`. Решение фиксируется в ADR-006.
- **DoD:** после установки в сайдбаре появляется Skills, страница показывает реальные скиллы проекта и их суммарный вес; переключение темы не ломает вёрстку; удаление бандла убирает страницу.
- **Оценка:** 35–55k, 3–4 ч.
- **Риск:** неверный слот/пропсы → пустая панель. Снимается первым же запуском.

### P2. Редактор

- Создание: форма + запись `<корень>/<имя>/SKILL.md`, валидация, отказ при дубликате имени в целевом слое.
- Правка описания/тела/`whenToUse`; переименование папки + `name` + предупреждение о ссылках.
- Удаление и «выключить/включить» (`disable-model-invocation`).
- Проверка: после записи watcher обновляет каталог, страница перечитывает список.
- **DoD:** цикл «создал → увидел в списке → поправил → выключил» проходит без перезапуска.
- **Оценка:** 40–60k, 3–4 ч.

### P3. Каталог и установка

- `catalog.json` (10 записей) в бандле + чтение состояния «установлен/нет».
- Экран каталога: категории, поиск, карточка с описанием, источником, лицензией, весом.
- Установка: скачать upstream (GitHub tarball по `repo`/`path`/`ref`), проверить наличие `SKILL.md` и frontmatter, скопировать только папку скилла, не выполнять никаких скриптов.
- Выбор: один / несколько / все; подтверждение с прогнозом бюджета; отчёт «установлено N, пропущено M».
- **DoD:** установка `docx` и категории «Документы» (4 скилла) из пустого проекта; повторная установка не дублирует; «все» показывает предупреждение.
- **Оценка:** 45–70k, 4–6 ч.
- **Риск:** сеть/лицензии. Снимается metadata-only каталогом и загрузкой по кнопке.

### P4. A/B-сравнение

- Хранилище версий: `<проект>/.dsh/skill-versions/<имя>/<метка>/SKILL.md`.
- Спайк изоляции: зарегистрировать вариант скилла только для конкретного агента через `agent.ctx.skills.register` в слое агента. Если не сработает — последовательный прогон (A, затем подмена файла на B) с сохранением транскриптов.
- UI: две панели, два чата, одна задача; кнопки «Запустить оба», «Лучше A / B / ничья».
- Авто-судья: отдельный вызов модели по рубрике (следование скиллу, полнота, краткость, корректность), результат — под двумя колонками.
- **DoD:** одна задача, две версии скилла, два независимых ответа, оценка; состояние переживает перезагрузку страницы.
- **Оценка:** 120–200k, 2–3 дня.
- **Риск:** высокий — изоляция скиллов по сессиям. Поэтому спайк первым делом; при провале — последовательная схема, срок тот же.

### P5. GitHub и релиз

- README с установкой, скриншоты, CHANGELOG, версия 0.1.0.
- `git init` → коммиты по этапам → remote → push (нужен ваш доступ).
- Опционально: CI (lint + сборка клиента), публикация в npm и в каталог dshmarket.

- **Оценка:** 20–30k, 2–3 ч.

## 5. Бюджет промпта

Каждый скилл добавляет в системный промпт `name + description + whenToUse`. Оценка: `ceil(длина_строк / 4)` токенов на скилл, плюс ~200 токенов накладных расходов каталога.

- 10 скиллов среднего размера ≈ 300–450 токенов на **каждый** запрос.
- Порог предупреждения по умолчанию — 1200 токенов (≈ 30–35 скиллов).
- «Выключить» = `disable-model-invocation: true`: скилл остаётся в `/`, но не в промпте модели. Это дешевле удаления и обратимо.

## 6. Как будет работать A/B

```
[Версия A: v3]  чат A  ─┐
                        ├─ одна задача → два ответа → оценка
[Версия B: v4]  чат B  ─┘
```

- Версии лежат отдельно от рабочего скилла, установка в проект — только на время прогона.
- Оба чата получают одинаковый текст задачи, одинаковую модель и одинаковые инструменты; различие — только версия скилла.
- Судья получает оба ответа и рубрику, возвращает вердикт и 2–3 причины. Ручная оценка всегда доступна и приоритетнее.

## 8. Что нужно от вас

1. **Разрешение на установку плагина** в профиль `desktop`. Установка влияет на все сессии профиля и откатывается удалением бандла; `plugin_manager` спросит подтверждение.
2. **Куда положить проект.** Сейчас он внутри `default-workspace/create-skills` (песочница разрешает запись только туда). Чтобы это была отдельная рабочая область, добавьте папку как workspace в сайдбаре — либо разрешите создать её рядом, вне песочницы, и я попрошу доступ.
3. **Каталог.** Подтвердить 10 скиллов (см. `catalog/catalog.json`): docx, pdf, pptx, xlsx, skill-creator, mcp-builder, webapp-testing, web-artifacts-builder, canvas-design, brand-guidelines — из `anthropics/skills`. У репозитория нет объявленной лицензии, поэтому контент не коммитим: только метаданные и загрузка по кнопке пользователя.
4. **GitHub.** Имя репозитория (`create-skills`?), публичный или приватный, и кто пушит: я подготовлю коммиты, но для push нужен ваш токен/доступ (или вы пушите сами).
5. **Язык интерфейса.** Предлагаю ru + en; основной — русский.
6. **A/B.** Кто оценивает по умолчанию — вы или авто-судья; какая модель у судьи.

## 9. Открытые вопросы

- Нужна ли установка «в пользовательский слой» (`~/.dsh/skills`) из UI или только в проект?
- Показывать ли в каталоге скиллы, которые уже встроены в DSH (office-*), с пометкой «уже есть»?
- Хранить ли историю версий скилла в репозитории проекта (`.dsh/skill-versions`) или в домашней папке плагина?
- Нужен ли импорт скилла из ZIP/папки, или достаточно каталога и создания с нуля?

## 10. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| Изоляция скиллов по сессии не сработает | средняя | спайк в P4; fallback — последовательный прогон |
| Слот/пропсы страницы не совпадут | низкая | первый же запуск P1; шаблон панели из dsh-context |
| Каталог тянет контент без лицензии | средняя | metadata-only + загрузка по кнопке, без коммита |
| Сеть недоступна при установке | средняя | ручной импорт папки как fallback |
| Бюджет промпта растёт незаметно | высокая | счётчик в шапке + порог + «выключить» |
